## Architecture guardrails

Machine-enforced rules from the baseline (IMP-0002):

- `ibapi` is allowed only inside `packages/py/broker-ibkr`; provider SDKs
  (FastAPI, SQLAlchemy, NATS, Playwright) only inside their adapter/app.
- `contracts` imports no internal packages; `domain` imports only `contracts`;
  the broker adapter is imported only by itself and `apps/execution-agent`.
- Canonical environments (`RESEARCH`/`PAPER`/`LIVE`) and operating modes are
  defined in `packages/py/config/src/trading_config/environments.py`. Unknown
  values fail explicitly; LIVE and PAPER_AUTO are prohibited by baseline;
  Paper and Live never share queue names or account allowlists.
- Forbidden patterns: hardcoded account ids, LIVE defaults, queue names mixing
  paper and live, embedded secrets, hardcoded Windows paths.

Run the guardrails:

```sh
uv run python scripts/check_architecture.py   # standalone checker
uv run pytest tests/architecture              # positive + negative tests
```

Architecture changes require an ADR (`docs/adr/ADR-0000-template.md`) and
user approval. Code ownership is defined in `.github/CODEOWNERS`.

## Canonical contracts (enums)

The single source of truth for canonical enums is
`packages/py/contracts/src/trading_contracts/enums.py` (IMP-0101); every value
is taken verbatim from the baseline documents. JSON Schemas
(`packages/schemas/json/enums/`) and TypeScript types
(`packages/ts/contracts-generated/src/enums.ts`) are **generated — never edit
them by hand**.

```sh
uv run python scripts/generate_contracts.py          # regenerate (idempotent)
uv run python scripts/generate_contracts.py --check  # drift check (runs in CI)
uv run pytest tests/contracts                        # value + parity tests
```

Adding an enum: define it in `enums.py` with its authority reference, append
it to `CANONICAL_ENUMS`, regenerate, and add its expected values to
`tests/contracts/test_enums.py`. Changing an existing enum requires a schema
version bump and a migration plan per the Data Model specification.

## Event envelope

Every event in the system is wrapped in the canonical `EventEnvelope`
(IMP-0102). Source of truth:
`packages/py/contracts/src/trading_contracts/envelope.py` (Pydantic model);
the JSON Schema (`packages/schemas/json/events/event_envelope.schema.json`)
and TypeScript (`packages/ts/contracts-generated/src/event-envelope.ts`) are
generated by the same `scripts/generate_contracts.py` / `--check` commands as
the enums — never edit them by hand.

The four point-in-time fields are distinct and all mandatory:

- `occurred_at` — when the event happened in the outside world.
- `observed_at` — when the source noticed it.
- `available_at` — the first moment the system was allowed to use it in a
  decision (point-in-time / replay boundary).
- `ingested_at` — when the system actually ingested it.

`correlation_id` groups every event of one logical flow; `causation_id` is
the `event_id` of the direct cause and is omitted on root events. All
timestamps must be timezone-aware; unknown fields are rejected.

```json
{
  "event_id": "0197a1b2-c3d4-7e5f-8a9b-0c1d2e3f4a5b",
  "type": "MESSAGE_CREATED",
  "version": "1.0",
  "occurred_at": "2026-07-05T10:00:00+00:00",
  "observed_at": "2026-07-05T10:00:01+00:00",
  "available_at": "2026-07-05T10:00:02+00:00",
  "ingested_at": "2026-07-05T10:00:03+00:00",
  "correlation_id": "0197a1b2-c3d4-7e5f-8a9b-0c1d2e3f4a5c",
  "causation_id": null
}
```

## Source / social contracts

Canonical source and social-message contracts (IMP-0103) live in
`packages/py/contracts/src/trading_contracts/social.py` (Pydantic source of
truth); JSON Schemas (`packages/schemas/json/social/`) and TypeScript
(`packages/ts/contracts-generated/src/social.ts`) are generated by the same
`scripts/generate_contracts.py` / `--check` commands. These are contracts,
not adapters — no service is ever contacted.

Models:

- `SocialConnectionProfile` — a configured connection (`provider`,
  `access_mode`, `identity_ref`, `required_capability`, `enabled`,
  `health_status`). The `access_mode`↔`provider` pair is validated:
  `WHATSAPP_USER`→WHATSAPP, `DISCORD_USER`→DISCORD,
  `TELEGRAM_USER_TDLIB`→TELEGRAM, `TELEGRAM_BOT`→TELEGRAM. Any other pairing
  (e.g. WhatsApp mode on Telegram) is rejected.
- `CanonicalSocialMessage` — the adapter-independent identity of a post.
- `SocialMessageObservation` — one user/bot capture of a canonical message
  (its `received_at` is the adapter-side receive time, distinct from the
  envelope's `ingested_at`).
- `SocialAttachment` — metadata + storage reference only, never raw bytes.

**Message vs observation:** a message is the deduplicated canonical post;
observations are the per-adapter sightings of it. User-mode and bot-mode
observations of the same post map to one message.

**Dedup key** (`compute_social_message_dedup_key`, SHA-256, stdlib):

```
dedup_key = "sha256:" + SHA256(source_type ␟ channel_external_id ␟ "id" ␟ external_message_id)
fallback  = "sha256:" + SHA256(source_type ␟ channel_external_id ␟ "content" ␟ content_hash)
```

Participating fields: `source_type`, `channel_external_id`, and
`external_message_id` (content hash as fallback when there is no native id).
Access mode, connector identity and ingestion timestamps are deliberately
excluded, so cross-mode duplicates collapse to one key. Edits keep the key
(revision bump); deletions keep the key (tombstone flag); an attachment does
not change the key; a forward is a new message linked by content cluster.

**Never in these contracts:** tokens, sessions, cookies, QR/session payloads
or credentials — `identity_ref`/`raw_object_ref`/`secret_ref` are opaque
references only, and negative tests assert credential-shaped fields are
absent.

## Baseline verification

The specification baseline in `docs/baseline-v0.5/` is hash-locked (IMP-0003):
`BASELINE_LOCK.json` pins the SHA-256 of every baseline file (CRLF normalized
to LF so hashes match across Windows and Linux), and
`CONTRACT_AUTHORITY_MAP.json` records which document is authoritative for
which contract area. Changing a baseline document without an explicit lock
update fails verification.

```sh
uv run python scripts/verify_baseline.py    # verify manifest, hashes, lock
uv run python scripts/build_metadata.py     # build record: versions + hashes
uv run pytest tests/baseline                # positive + negative tests
```

Regenerating the lock (`--update`) is an explicit, reviewed action.
